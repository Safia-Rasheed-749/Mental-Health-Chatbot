# Dataset provenance and licensing register

This register intentionally distinguishes files present in the checkout from facts that have not yet been evidenced. Do not treat a filename, model card, or project recollection as a license grant.

## Structured verification register

`PROVENANCE.csv` is the row-level source-of-truth worksheet. It captures upstream owner/URL, immutable revision, access date, license terms and evidence, allowed uses, attribution, personal-data review, transformations, split method, reviewer role, and verification status. Blank fields and `UNVERIFIED` are explicit blockers, not implied permission. Run `python backend/scripts/check_dataset_provenance.py`; a nonzero exit means human/source confirmation remains. For a `VERIFIED` entry, attach an authoritative license/terms snapshot or citation at `license_evidence_path` and record the exact revision and access date. Do not mark a dataset verified from repository recollection alone.

`backend/scripts/audit_datasets.py` produces row counts, label balance, missing values, exact duplicate counts and near-duplicate overlap flags. It does not establish legal provenance or data consent. See `dataset_audit.json` after running it. Any near-duplicate result marked skipped is unknown, not a pass.

For new, separate deduplicated data copies, use `backend/scripts/create_deduplicated_splits.py` with explicit `--split` arguments and a complete audit JSON. This will not edit originals; inspect its `DEDUPLICATION_MANIFEST.json`, resulting row counts, labels, and hashes before training. It removes evaluation-side exact and audited near-duplicate overlaps against train, but approximate LSH candidates do not guarantee all near duplicates were detected. Retrain and reevaluate to claim leakage-adjusted model performance.

For saved, row-aligned classifier probabilities, `backend/scripts/evaluate_leakage_adjusted.py` filters test rows overlapping the training text or audit near-duplicate candidates, then writes accuracy/macro-F1 bootstrap CIs, multiclass Brier score, and calibration-bin CSV. It requires full class-probability columns (`prob_<label>`), refuses confidence-only data, and is a post-hoc sensitivity analysis on the original fitted model—not deduplicated retraining or a cure for model-selection leakage.

## Training/evaluation evidence limitations

- Depression archived notebook evidence records seed 42 and a three-epoch RoBERTa/DistilBERT/DeBERTa comparison, but the actual local training notebook is a Colab notebook with cloud paths and the retained local production model/training script is absent from this checkout. It is not currently a clean-machine training reproduction.
- Stress training script `backend/app/ai/stress_detection/train.py` specifies RoBERTa-base, max length 128, 5 epochs, learning rate 2e-5, batch size 8, weight decay 0.01, validation on the file named `clean_test.csv`, and automatic resume from latest checkpoint. That setup makes the test file a validation/selection input and is not a clean held-out protocol. Its output location is current-working-directory-relative and no fixed seed is set in that script.
- Emotion benchmark evidence identifies the DAIR-AI `dair-ai/emotion` official splits and a seed 42 comparison, but does not provide prediction CSVs in the retained comparison folder. Per-example held-out metrics cannot be recomputed from predictions here.
- The audited local `counsel_chat/emotion_dataset/{raw,processed}` directory is a separate local dataset collection and must not be assumed to be the `dair-ai/emotion` official split. The exact remote revision/retrieved cache used by the emotion notebook is not pinned in this checkout; that leaves the active emotion training data split audit incomplete.
